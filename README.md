# Knowledge Base Builder · 知识库搭建访谈官

一个 WorkBuddy Skill。通过**渐进式问答访谈**，把用户脑子里说不清、没时间整理的行业经验逐层问出来，实时结构化，最终整合为模块化的知识库文档。

> 核心判断：知识库的价值不在「整理」，在「萃取」。用户脑子里有答案，缺的是一套提问顺序把它逼出来。本 skill 提供的正是这套提问顺序。

---

## 它解决什么问题

大多数人搭知识库会卡在同一个地方：**知道要沉淀，但坐下来写不出东西**。方法论、客户洞察、内容标准都散在脑子里和聊天记录里，没有结构，也没有被逼出来的契机。

本 skill 不做信息收集，做**判断萃取**——一轮只问 2-3 个问题，就着用户回答的具体场景深挖，把原始素材提炼成方法论级别的判断。

## 工作流

| 阶段 | 内容 |
|------|------|
| Step 0 | 开场确认：行业、用途、Obsidian Vault 输出路径 |
| Step 1 | 渐进式访谈：Phase A 基础洞察（必做）→ Phase B 内容资产（内容获客行业启用）→ Phase C 整合归一 |
| Step 2 | 实时结构化记录，逐轮归入 19 项模块 |
| Step 3 | 整合补齐：P0 关键缺失追问，非关键缺失标注待采集 |
| Step 4 | 按模板生成知识库 Markdown，写入 Obsidian Vault（已存在则合并，不覆盖） |
| Step 5 | 交付：模块完成度概览 + 优先级最高的待补充项 |

### 三个阶段的访谈内容

- **Phase A 基础洞察**（任何行业必做）
  - A1 客户画像与人群理解：年龄、一天推演、身份圈层、购买动机、深层动机、日常性疼痛
  - A2 决策路径复盘：常驻平台、从契机到下单的完整链路、最打动点
  - A3 成交行为与 SOP：私域动作、话术、发圈节奏、成交客户开口第一句
- **Phase B 内容资产**（内容获客类行业启用，不涉及则自动裁剪）
  - B1 素材形式 / B2 对标拆解 / B3 爆款框架 / B4 热点借势 / B5 平台规则与违禁词
- **Phase C 整合归一**：归入 19 项模块并输出文档

## 安装

### 方式一：复制目录

把整个 `knowledge-base-builder` 目录放进 WorkBuddy 的技能库：

| 系统 | 用户级路径（装一次，所有项目可用） |
|------|-----------------------------------|
| Windows | `C:\Users\<你的用户名>\.workbuddy\skills\` |
| macOS / Linux | `~/.workbuddy/skills/` |

```bash
# macOS / Linux
cp -r knowledge-base-builder ~/.workbuddy/skills/

# Windows PowerShell
Copy-Item -Recurse knowledge-base-builder "$env:USERPROFILE\.workbuddy\skills\"
```

**团队共享**则放进项目根目录的 `.workbuddy/skills/`，随代码仓库走——成员拉代码就自动拥有，无需各自安装。

### 方式二：导入 zip

用 `knowledge-base-builder.zip` 直接导入（WorkBuddy 支持从 zip 安装技能），或解压后按方式一放置。

### 验证

放好后刷新 WorkBuddy 技能列表，能看到 `knowledge-base-builder` 即安装成功。对话里说一句「帮我搭个知识库」就会触发。

## 知识库 19 项模块

按优先级分层，决定「缺失时是追问补齐还是留空标注」：

| 级别 | 模块 |
|------|------|
| **P0 核心** | 01 行业判断标准 · 07 获客底层方法论 · 11 人群受众 · 17 消费者购买路径 |
| **P1 重要** | 02 文案基础标准 · 05 写作风格标准 · 09 表层痛点 · 10 深层需求 · 12 爆款标题 |
| **P2 增强** | 03 爆款案例 · 04 真实评论 · 06 硬性要求 · 08 心理技巧 · 13 热点热梗 · 14 tag · 15 同行话术 · 16 平台规则 |
| **P3 数据** | 18 平台关键词数据 · 19 衍生关键词（通常需工具采集） |

模块 01「行业判断标准」含 15 条方法论，是全库核心，其余模块是它的具体展开。

## 设计原则

1. **一次只问 2-3 个问题**——绝不把几十个问题一次丢给用户
2. **先问透再往下走**——回答含糊时就着该点追问具体场景，不跳过、不替用户作答
3. **实时记录，不丢信息**——逐轮归入模块，不依赖事后回忆
4. **允许跳过与模糊**——答不上来时给参考示例帮用户开口，或标记待补
5. **给进度感**——每轮确认收获 + 预告下一步
6. **萃取优先于记录**——提炼为方法论级别的判断，而非照搬原话
7. **不静默编造**——任何推演内容必须标注为「推测」

## 触发场景

用户提到以下意图时触发：搭建知识库、沉淀行业经验、萃取方法论、整理行业资产、客户画像访谈、账号定位访谈、把经验变成可复用文档、整理我的方法论。

适用于小红书获客、代写、咨询、电商、知识付费、实体门店等任何需要沉淀行业 know-how 的领域。

## 使用示例

```
用户：帮我搭个知识库
 → skill 开场确认行业、用途、Obsidian 路径

用户：我做代写，想给团队用
 → 进入 Phase A1，问 2-3 个客户画像问题

用户：（回答）
 → 复述萃取到的判断请用户确认 → 预告下一轮 → 继续追问

...若干轮后...
 → 整合 19 模块 → 写入 Obsidian → 给出完成度概览与待补充项
```

后续丢新素材、新案例时可随时继续补充，追加进对应模块即可。
